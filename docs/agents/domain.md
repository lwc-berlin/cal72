# Domain docs

This repository uses a single-context layout:
- GLOSSARY.md at the repository root.
- docs/adr/ for architecture decisions.

Before exploring, read the glossary and ADRs relevant to the work.
If GLOSSARY-MAP.md exists later, follow its pointers to relevant glossaries.

If these files are absent, proceed silently. Do not propose creating them
upfront; domain-modeling creates them lazily as terms and decisions resolve.

Use the glossary's vocabulary in issues, proposals, hypotheses, and tests.
Reconsider invented synonyms; note genuine vocabulary gaps for domain-modeling.

Surface any conflict with an existing ADR explicitly rather than silently
overriding it.
